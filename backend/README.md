# Бэкенд мониторингового сервиса

## Запуск через Docker

Команды выполняются из корня репозитория.

1. Если `.env` ещё нет, скопируйте `.env.example` в `.env`.
2. Укажите все настройки из [Инструкции](#настройки-env)

Запуск происходит с помощью команды:
```
docker compose up -d --build
```

Проверка запуска:
```
docker compose ps
docker compose logs --tail 100 backend
```

Compose поднимает БД, ждёт её готовности, применяет миграции и запускает backend, затем frontend.
Документация доступна по ссылке: http://localhost:8000/docs

### Совместный запуск с фронтендом

Фронтенд находится в отдельном репозитории. По умолчанию Compose ожидает его в `../../Frontend/monitoring-service` относительно `docker-compose.yaml`. В этой папке должны находиться `package.json`, `Dockerfile`, `nginx.conf` и исходники. Если папка другая, укажите её в `.env` через `FRONTEND_CONTEXT` (для Windows используйте прямые слеши, например `C:/Projects/monitoring-frontend`).

```powershell
docker compose up -d --build
```

Сайт: http://localhost:8080. Вход — учётной записью администратора бэкенда. Nginx раздаёт собранный фронтенд и перенаправляет `/api/*` в `backend:8000`, убирая префикс `/api`. Для этого режима отдельная настройка CORS не требуется. Исходники и Node.js в работающем контейнере не нужны.

По умолчанию сайт доступен только на этом компьютере. Для доступа по LAN/VPN задайте `FRONTEND_BIND_HOST=0.0.0.0` и откройте `http://IP-сервера:8080`. Через тот же адрес агент может отправлять данные, если его `SERVER_URL` равен `http://IP-сервера:8080/api`.

Только бэкенд и БД можно запустить без папки фронтенда: `docker compose up -d --build backend`. После изменения фронтенда пересоберите его: `docker compose up -d --build frontend`. Для запуска готовых образов на другом компьютере сначала опубликуйте образ фронтенда; локальный тег `monitoring-frontend:local` сам по себе не доступен для скачивания.

В будущем добавим в `main` образ backend, который можно будет скачать и не собирать образ для развертывания приложения.

Существующие устройства и метрики сохраняются при миграции. Для старых устройств без хеша токена задайте токен через PUT /devices/{id}/agent-token. 
Фоновая очистка удаляет измерения старше RETENTION_DAYS (в .env файле задается). 
`docker compose down` не удалит данные из БД, если же данные нужно удалить то добавьте `-v`.

## Разработка

Запустите только БД из корня: `docker compose up -d db`. Если backend-контейнер уже запущен, остановите его: `docker compose stop backend`.

Затем из каталога backend с активированным .venv:

```powershell
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m uvicorn app.main:app --reload
```

## API сервиса

В таблице **Сессия** означает заголовок `Authorization: Bearer <access_token>`, **Агент** - `X-Agent-Token: <agent_token>`.

| Метод и путь | Назначение | Авторизация | Успешный ответ | Ошибки |
| --- | --- | --- | --- | --- |
| `GET /health` | Проверить, что API работает, без обращения к БД | Не нужна | **200** - `{"status":"ok"}` | Специальные ошибки не предусмотрены |
| `GET /health/database` | Проверить соединение с БД запросом `SELECT 1` | Не нужна | **200** - `{"status":"ok"}` | **503** - проверка БД не прошла |
| `POST /auth/login` | Войти по `username` и `password` | Не нужна | **200** - `access_token`, `token_type="bearer"`, `expires_in` в секундах | **401** - неверный логин или пароль; **422** - неверные входные данные; **429** - превышен лимит попыток |
| `GET /auth/me` | Получить пользователя текущей сессии | Сессия | **200** - `{"id":1,"username":"admin"}` | **401** - сессия отсутствует, недействительна или истекла |
| `POST /auth/logout` | Завершить текущую сессию | Сессия | **204** - без тела ответа | **401** - сессия отсутствует, недействительна или истекла |
| `POST /devices` | Создать устройство: `name` и `agent_token` | Сессия | **201** - созданное устройство | **401** - нет действующей сессии; **409** - токен занят; **422** - неверные поля |
| `GET /devices` | Получить список с поиском, фильтром статуса и пагинацией | Сессия | **200** - массив устройств с последними метриками; заголовок `X-Total-Count` | **401** - нет действующей сессии; **422** - неверные параметры запроса |
| `GET /devices/{device_id}` | Получить устройство и его последние метрики | Сессия | **200** - устройство | **401** - нет действующей сессии; **404** - устройство не найдено; **422** - неверный ID |
| `PATCH /devices/{device_id}` | Переименовать устройство: `{"name":"Новое имя"}` | Сессия | **200** - обновлённое устройство | **401** - нет действующей сессии; **404** - устройство не найдено; **422** - неверное имя или ID |
| `PUT /devices/{device_id}/agent-token` | Заменить токен: `{"agent_token":"..."}` | Сессия | **200** - устройство без токена и его хеша; прежний токен отозван | **401** - нет действующей сессии; **404** - устройство не найдено; **409** - токен занят; **422** - неверный токен или ID |
| `DELETE /devices/{device_id}` | Удалить устройство и всю его историю | Сессия | **204** - без тела ответа | **401** - нет действующей сессии; **404** - устройство не найдено; **422** - неверный ID |
| `GET /devices/{device_id}/metrics/latest` | Получить последнее измерение в пределах срока хранения | Сессия | **200** - объект измерения | **401** - нет действующей сессии; **404** - устройство не найдено или нет измерений; **422** - неверный ID |
| `GET /devices/{device_id}/metrics` | Получить историю для графиков: `start`, `end`, `max_points` | Сессия | **200** - `device_id`, `start`, `end`, `step_seconds`, массив `points` | **401** - нет действующей сессии; **404** - устройство не найдено; **422** - неверный ID, период или параметры |
| `GET /agent` | Агенту узнать устройство, которому принадлежит его токен | Агент | **200** - устройство; `latest_metrics=null`, метрики не загружаются | **401** - токен отсутствует или не распознан |
| `POST /metrics` | Агенту отправить измерение; устройство определяется по токену | Агент | **201** - сохранённое измерение с `id`, `device_id` и `received_at` | **401** - токен отсутствует, не распознан или отозван; **422** - неверные показатели или время |

Пустой список устройств - это **200** с `[]`. Отсутствие истории у существующего устройства - **200** с `points=[]`. У ручки последних метрик отсутствие измерений означает **404**.

GET /devices возвращает массив. Параметры: limit=10 (1–100), offset=0, search (по части имени без учёта регистра), status=online или offline. Заголовок X-Total-Count содержит общее число устройств с учётом фильтров.

Устройство содержит id, name, created_at, last_seen_at, status, latest_metrics. last_seen_at равен времени последнего успешно принятого сервером измерения. Если сообщений ещё не было, значение null, статус offline. latest_metrics=null означает отсутствие измерений в пределах срока хранения. Наличие старого измерения само по себе не означает online. GET /agent не загружает latest_metrics.

GET /devices/{id}/metrics/latest возвращает 404, если устройство или измерения не найдены. Все даты содержат часовой пояс. На фронтенде их можно отображать в локальном времени.

### Поля ответов API

#### Устройство — DeviceResponse

Возвращается при создании, чтении, переименовании устройства и замене токена, а также из `GET /agent`. `GET /devices` возвращает массив таких объектов; `X-Total-Count` передаётся отдельно в заголовке ответа.

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | integer | ID устройства |
| `name` | string | Название устройства |
| `created_at` | string | Дата регистрации, ISO 8601 |
| `last_seen_at` | string или null | Время последнего принятого измерения; null, если сообщений ещё не было |
| `status` | string | `online` или `offline` |
| `latest_metrics` | object или null | Последнее измерение в формате MetricsResponse |

Токен агента и его хеш не возвращаются. В `GET /agent` поле `latest_metrics` равно `null`, поскольку эта ручка не загружает измерения.

#### Измерение — MetricsResponse

Возвращается из `POST /metrics`, `GET /devices/{device_id}/metrics/latest` и внутри `latest_metrics` устройства.

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | integer | ID измерения |
| `device_id` | integer | ID устройства |
| `collected_at` | string | Время сбора агентом, ISO 8601 |
| `received_at` | string | Время получения сервером, ISO 8601 |
| `cpu_percent` | number или null | Загрузка CPU, от 0 до 100% |
| `memory_used_bytes` | integer или null | Используемая оперативная память в байтах |
| `memory_total_bytes` | integer или null | Общий объём оперативной памяти в байтах |
| `disks` | array или null | Массив объектов DiskMetrics |
| `services` | object или null | Состояния служб, например `{"Spooler":"running"}`; ключи и значения — строки |

#### Диск — DiskMetrics

Структура одного элемента массива `disks` в измерении или точке истории.

| Поле | Тип | Описание |
| --- | --- | --- |
| `name` | string | Точка монтирования, например `C:\` или `/` |
| `disk_used_bytes` | integer | Занятое место в байтах |
| `disk_total_bytes` | integer | Общий объём в байтах |

#### История метрик — MetricsHistory

Возвращается из `GET /devices/{device_id}/metrics`.

| Поле | Тип | Описание |
| --- | --- | --- |
| `device_id` | integer | ID устройства |
| `start` | string | Начало выбранного периода, ISO 8601 |
| `end` | string | Конец выбранного периода, ISO 8601 |
| `step_seconds` | integer | Размер интервала группировки в секундах |
| `points` | array | Массив объектов HistoryPoint; при отсутствии измерений — `[]` |

#### Точка истории — HistoryPoint

| Поле | Тип | Описание |
| --- | --- | --- |
| `bucket_start` | string | Начало интервала, ISO 8601 |
| `samples` | integer | Количество измерений в интервале |
| `cpu_percent` | number или null | Средняя загрузка CPU |
| `cpu_max_percent` | number или null | Максимальная загрузка CPU |
| `memory_used_bytes` | number или null | Среднее значение используемой памяти в байтах |
| `memory_total_bytes` | number или null | Среднее значение общего объёма памяти в байтах |
| `disks` | array или null | Диски из последнего измерения интервала в формате DiskMetrics, без усреднения |

#### Авторизация — ответ POST /auth/login

| Поле | Тип | Описание |
| --- | --- | --- |
| `access_token` | string | Токен сессии |
| `token_type` | string | Сейчас — `bearer` |
| `expires_in` | integer | Срок действия сессии в секундах |

#### Пользователь — ответ GET /auth/me

| Поле | Тип | Описание |
| --- | --- | --- |
| `id` | integer | ID пользователя |
| `username` | string | Имя пользователя |

#### Проверка работоспособности — успешный ответ GET /health и GET /health/database

| Поле | Тип | Описание |
| --- | --- | --- |
| `status` | string | При успешной проверке — `ok` |

Ответы `204` не содержат тела, для них не нужно вызывать `response.json()`.

Интерактивная документация доступна по `/docs`, схема API в формате OpenAPI — по `/openapi.json`.

### Графики

GET /devices/2/metrics?start=2026-09-30T08:00:00Z&end=2026-09-30T10:00:00Z&max_points=500

start/end необязательны, по умолчанию последние 24 часа. max_points от 1 до 1000, по умолчанию 500. Период ограничивается сроком хранения. start должен быть меньше end, а end не может быть дальше пяти минут в будущем.

Ответ: device_id, start, end, step_seconds, points. Каждая точка содержит bucket_start, samples, средние cpu_percent, memory_used_bytes, memory_total_bytes и максимальную cpu_max_percent. Поле disks содержит диски из последнего измерения интервала, без усреднения. Состояния служб в историю не входят. Интервалы группировки отсчитываются от start, диапазон включает start и исключает end.

NULL-показатели не участвуют в среднем, полностью отсутствующий показатель остаётся null. Интервалы без измерений пропускаются, фронтенд должен рисовать разрыв, а не ноль.

### Ошибки

Обычные ошибки: `{"detail":"описание"}`

| Поле | Тип | Описание |
| --- | --- | --- |
| `detail` | string или array | Сообщение об ошибке либо массив ошибок проверки входных данных |

Если `detail` — массив, каждый элемент имеет следующую структуру:

| Поле | Тип | Описание |
| --- | --- | --- |
| `loc` | array | Расположение ошибки, например `["body", "name"]`; элементы — строки или целые числа |
| `msg` | string | Описание ошибки |
| `type` | string | Код типа ошибки |

При `422` возможны оба варианта: ошибки проверки входных данных возвращаются массивом, а некоторые проверки периода истории — строкой.

- 401 - неверный/отсутствующий токен или истёкшая сессия.
- 404 - устройство или последние метрики не найдены.
- 409 - токен уже назначен другому устройству.
- 413 - тело запроса больше 64 КиБ.
- 422 - неверные поля, значения или период.
- 429 - более 10 попыток входа за минуту с одного адреса, Retry-After: 60.
- 503 - ошибка работы с БД.

Общие ошибки для [API](#api-сервиса):

- **503** - ошибка работы с БД для любой ручки, которая к ней обращается (все перечисленные в таблице, кроме `GET /health`).
- **413** - превышен `MAX_REQUEST_BYTES` для `POST`, `PUT` и `PATCH`, по умолчанию 64 КиБ.

## Контракт агента

Пользователь задаёт одинаковый токен в настройках агента и при добавлении устройства. Длина 32–128 символов, разрешены A–Z, a–z, цифры, дефис и подчёркивание. Используйте случайное значение, сервер хранит только SHA-256 и не возвращает токен или его хеш. 
Получить случайный токен локально можно командой `python -c "import secrets; print(secrets.token_urlsafe(32))"`.

## Настройки .env

Настройки задаются в `.env` в корне репозитория. В таблице указаны значения по умолчанию из кода и Compose; значения в `.env.example` _ примеры заполнения.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `POSTGRES_HOST` | `127.0.0.1` | Адрес PostgreSQL |
| `POSTGRES_PORT` | `5435` | При локальном запуске порт подключения к БД. В Compose значение из `.env` определяет порт БД на компьютере, а бэкенд внутри сети всегда подключается к `db:5432` |
| `POSTGRES_USER` | _| Пользователь PostgreSQL |
| `POSTGRES_PASSWORD` | _ | Пароль пользователя PostgreSQL |
| `POSTGRES_DB` | _ | Имя базы данных |
| `ADMIN_USERNAME` | `admin` | Имя первого администратора, используемое при его создании |
| `ADMIN_PASSWORD` | _ | Пароль для создания первого администратора, 12–256 символов |
| `SESSION_HOURS` | `12` | Длительность пользовательской сессии, от 1 до 168 часов |
| `RETENTION_DAYS` | `7` | Срок хранения метрик, от 1 до 365 дней (отсчитывается от времени сбора `collected_at`) |
| `CLEANUP_INTERVAL_SECONDS` | `60` | Интервал фонового удаления старых метрик и истёкших сессий, в секундах (минимум 10) |
| `ONLINE_TIMEOUT_SECONDS` | `180` | Сколько секунд после последнего принятого измерения считать устройство online (минимум 10) |
| `CORS_ORIGINS` | `[]` | JSON-массив адресов фронтенда с протоколом и портом, без пути |
| `MAX_REQUEST_BYTES` | `65536` | Максимальный размер тела `POST`, `PUT` и `PATCH` в байтах (минимум 1024. По умолчанию 64 КиБ) |
| `CLEANUP_ENABLED` | `true` | `true` _ включить фоновую очистку, `false` _ отключить. Даже при отключении чтение метрик ограничено сроком хранения, а истёкшие сессии недействительны |
| `BACKEND_PORT` | `8000` | Порт API на компьютере при запуске через Compose. Внутри контейнера API слушает порт 8000 |
| `BACKEND_IMAGE` | `monitoring-backend:local` | Имя и тег Docker-образа бэкенда для Compose |
| `FRONTEND_CONTEXT` | `../../Frontend/monitoring-service` | Путь к исходникам фронтенда для сборки, относительно Compose |
| `FRONTEND_IMAGE` | `monitoring-frontend:local` | Имя и тег образа фронтенда |
| `FRONTEND_PORT` | `8080` | Порт сайта на компьютере |
| `FRONTEND_BIND_HOST` | `127.0.0.1` | Адрес публикации сайта; `0.0.0.0` — все сетевые интерфейсы |

`ADMIN_USERNAME` и `ADMIN_PASSWORD` используются только для создания первого пользователя.

При существующем томе PostgreSQL изменение `POSTGRES_USER`, `POSTGRES_PASSWORD` или `POSTGRES_DB` в `.env` само по себе не меняет пользователя, пароль или базу

После изменения `.env` перезапустите API или выполните `docker compose up -d`, чтобы Compose пересоздал контейнер с обновлённым окружением.
